# 웨딩 준비 타임라인 — 공유 체크리스트 설계

날짜: 2026-08-28
상태: 승인됨 (사용자 확인)

## 배경 / 문제

`index.html` 하나로 Vercel(`wedding-timeline` 프로젝트)에 운영 중인 웨딩 준비 체크리스트.
현재 구현은 테이블 **HTML 전체를 localStorage에 저장**하기 때문에:

1. 파일을 배포해도 저장된 옛 HTML이 화면을 덮어써서 디자인/내용 변경이 반영되지 않음.
2. localStorage는 브라우저별 저장소라 기기·브라우저 간 데이터 공유 불가.
3. 4열 `<table>` 레이아웃이 모바일에서 시인성이 나쁨.

## 요구사항

1. 파일 업데이트·디자인 변경 후에도 체크(및 편집) 데이터 유지.
2. 여러 사용자가 다른 기기·브라우저에서 접속해도 같은 체크리스트 데이터 표시.
3. 모바일 시인성 최적화.

사용자 결정 사항:
- 저장소: **Vercel KV (Upstash Redis, Vercel Marketplace 무료 플랜)**
- 공유 범위: **체크박스 + 항목 편집 전부** (텍스트 수정, 행/항목 추가·삭제, 핵심 토글, 제목/부제/푸터)

## 아키텍처

핵심 전환: "HTML 저장" → "구조화된 데이터 저장 + 클라이언트 렌더링".

### 데이터 모델 (Redis에 JSON 하나)

```json
{
  "rev": 12,
  "meta": { "title": "...", "sub": "...", "foot": "..." },
  "columns": ["DAY", "결혼식·신혼여행", "웨딩패키지·한복·예복", "혼수·신혼집·기타"],
  "rows": [
    {
      "id": "r-xxxx",
      "label": "D-365",
      "sub": "약 12개월 전",
      "cells": [
        { "items": [ { "id": "i-xxxx", "text": "...", "key": true, "checked": false } ], "tip": "..." }
      ]
    }
  ]
}
```

- `rev`: 낙관적 동시성 제어용 정수. 쓰기마다 +1.
- 항목/행 `id`: 생성 시 부여되는 불변 랜덤 id.
- 텍스트는 순수 문자열(플레인 텍스트)로 저장 — XSS 방지를 위해 렌더링 시 textContent로만 주입.

### 서버 (Vercel Serverless Function, 의존성 0)

`api/state.js` — Node 런타임, `fetch`로 Upstash REST API 직접 호출.
환경변수: `KV_REST_API_URL`/`KV_REST_API_TOKEN` 또는 `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN` 중 존재하는 것 사용.

- `GET /api/state` → `200 {rev, doc}` 또는 데이터 없으면 `200 {rev: 0, doc: null}`.
- `PUT /api/state` body `{baseRev, doc}`:
  - `baseRev == 현재 rev` → 저장, rev+1, `200 {rev}`.
  - 불일치 → `409 {rev, doc}` (최신본 반환).
- 환경변수 미설정 → `503 {error: "kv-not-configured"}`.

CAS는 GET-비교-SET 방식(서버리스 특성상 수 ms 경쟁 창 존재). 사용자 2명 규모에서 수용.

### 클라이언트 (index.html)

- 로드 시 `GET /api/state`. `doc:null`이면 index.html에 내장된 기본 데이터(시드)를 렌더 후 PUT으로 시드 저장.
- 렌더링: JSON → DOM 생성. 마크업/CSS는 항상 배포된 최신 파일 것 → 디자인 변경이 데이터와 무관하게 반영.
- 변경 흐름: 사용자 조작 → 로컬 doc 뮤테이션(op) 적용 → 400ms 디바운스 후 PUT.
  - 409 응답 시: 서버 doc 위에 보류 중인 op를 재적용 후 재시도(최대 수회).
- 폴링: 5초 간격 GET(rev 비교). 원격이 새 rev면 재렌더. 단, contenteditable 편집 중(포커스)일 때는 편집 종료 후 반영.
- 오프라인/서버 미연결: localStorage에 doc 캐시 + 보류 op 저장, 재접속 시 재시도. 상태줄에 "동기화됨 HH:MM / 오프라인 — 연결되면 자동 저장 / 서버 저장소 미연결" 표시.
- 기존 localStorage(v1, HTML 저장분)에서 체크 상태·텍스트를 1회 마이그레이션 시도하지 않음 — 현 운영 데이터가 기본 표와 동일 구조라면 시드가 곧 최신이므로 불필요(사용자가 이미 체크한 내용이 있으면 기기 1대에서 다시 체크). 단, v1 키는 정리.

### 인증 / 보안

- 인증 없음: URL을 아는 사람은 읽기/쓰기 가능(현재와 동일 수준, 수용된 트레이드오프).
- 서버는 doc 크기 상한(256KB)과 JSON 스키마 대략 검증(rows 배열 여부 등)만 수행.

## 모바일 최적화

- `<table>` → div 기반 레이아웃으로 전환.
  - 데스크톱(≥761px): CSS grid로 지금과 같은 4열 표 모양 유지.
  - 모바일: 날짜별 **카드 세로 스택**. 카드 헤더에 D-라벨 + 날짜 부제 + 진행률(예: 3/8), 카테고리 제목 아래 항목 나열.
- 터치 타깃: 체크박스를 22px로 확대하고 체크박스 히트 영역(패딩 포함)을 44×44px 이상으로 확보. 텍스트 탭은 지금처럼 편집 진입. 항목 행 최소 높이 44px.
- 폰트 크기 모바일에서 상향(항목 15px 내외), 행 간격 확대.
- 인쇄 스타일은 표 형태 유지(grid 기반으로 재현).

## 유지되는 기존 기능

행 추가/삭제, 항목 추가/삭제, 핵심 토글, 제목·부제·푸터 편집, 체크 초기화, 인쇄/PDF, HTML로 저장(현재 화면 스냅샷 다운로드), 저장 내용 지우기(서버 데이터 삭제 후 기본 표로 재시드 — 확인 대화 필수).

## 트레이드오프 (수용됨)

- 첫 시드 이후 내용의 원본은 서버 데이터. 파일의 기본 표를 고쳐도 기존 서버 데이터는 유지("저장 내용 지우기"로 재시드 가능).
- 동시 편집 충돌은 rev 기반 재시도로 해소하되, 수 ms 수준의 서버 경쟁 창은 존재.
- 인증 없음.

## 배포 / 설정

1. (사용자) Vercel 대시보드 → Storage → Upstash Redis 생성 → `wedding-timeline` 프로젝트에 연결.
2. `vercel deploy --prod` (api/ 디렉터리 자동 인식, 별도 빌드 설정 불필요).
3. 저장소 연결 전에도 배포 가능 — 페이지는 "서버 저장소 미연결" 상태로 localStorage 폴백 동작.
